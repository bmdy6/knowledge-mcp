# knowledge-search

用 MCP 在仓库里找到人该看的那一行。搜索是只读的，可以随时调用。

## 什么时候用哪个工具

| 想要 | 用 |
| --- | --- |
| 按关键词找内容 | `search(scope, query, limit)` |
| 看某个目录下有什么 | `list_documents(scope, prefix)` |
| 读整篇原文 | `read(scope, path)` |
| 只读命中附近几行 | `read_range(scope, path, start_line, end_line)` |
| 检查全库元数据是否合规 | `validate_vault(scope)` |

`scope` 只能是 `personal` 或 `company`，必须显式给。不要用一次调用去猜 scope。

## 搜索怎么给结果

按相关度排序，不是按文件路径。每条包含 `path`、`line_start`、`line_end`、`title`、`snippet`。

排序用的是 BM25 加标题加权：标题命中查询词的排前，英文技术词（`asyncio`、`pydantic`）比中文口语词权重高，`README.md`、`学习方法/学习点索引.md` 这类导航页被压低。

这意味着两件事：

- **行号定位到选中的命中章节或元数据行**，不保证是文档里第一条字面命中。要确认上下文就 `read_range` 把前后几行读出来。
- **不要只看第一条**。默认 `limit` 是 20，相关的可能在第 3-5 条。回答前至少扫一遍前几条的标题。

搜索默认不含 `archive/`。需要历史材料才传 `include_archive=true`。

## 回答怎么写

先给 `path:line` 和原文片段，再给摘要。顺序不能反——人要先能核实，才愿意看你理解得对不对。

- 每条结论后面跟 `path:line`，让人能直接跳过去；
- 引用原文时用原文，不要改写后再当引用；
- 多篇命中时按相关度列出，别合并成一段综述；
- 搜不到就说搜不到，给出试过的关键词，不要编一条看起来合理的答案；
- 涉及"这条内容是否可信"时，说明它的 `status`（`review` 是写入时固定的历史字段，不代表内容未经人确认——确认发生在使用时，AI 指出位置、人回原文核实）。

## 常见错误

- **只给摘要不给行号**：人无法核实，等于没找到。
- **跨 scope 混答**：`personal` 的结果里混进公司资料。搜索已经隔离，但你转述时不要把两边内容拼在一起。
- **把索引页当结论来源**：`学习方法/学习点索引.md`、`README.md` 的主题地图是导航，不是原文。点进去看它指向的文章。
- **把 `status` 当确认标记**：新文档创建时固定为 `review`，它不代表是否经过人确认。引用前说明出处（`scope + path + 行号`），让人自己回原文核实。
