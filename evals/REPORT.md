# 可选模型重排评测（Issue #8）

2026-11-23。本次建议保留默认关闭：公开合成集的排序改善明显，私有集收益较小且有退步，CPU 延迟增加。没有调整 BM25 参数，也没有根据分数修改问题、期望路径或公开语料。

## 结果

每组 40 题，每题一个期望文档。Recall@k 为前 k 条命中期望路径的题目比例；MRR 截断于 10，未命中计 0。延迟单位为 ms。

| 集合 / 模式 | Recall@1 | Recall@5 | Recall@10 | MRR@10 | p50 | p95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 公开 BM25 | 67.5% | 85.0% | 90.0% | 0.7656 | 3.31 | 4.24 |
| 公开重排 | 80.0% | 90.0% | 90.0% | 0.8500 | 24.07 | 112.32 |
| 私有 BM25 | 55.0% | 92.5% | 97.5% | 0.6983 | 445.12 | 698.35 |
| 私有重排 | 57.5% | 90.0% | 97.5% | 0.7155 | 2534.87 | 3406.34 |

公开集：p50 增加 20.76 ms（7.28 倍），p95 增加 108.08 ms（26.49 倍）。私有集：p50 增加 2089.75 ms（5.69 倍），p95 增加 2707.99 ms（4.88 倍）。这是端到端搜索耗时，包括读盘、BM25、片段提取和重排，不是单独的 ONNX 推理时间。公开短文集的候选通常较少；私有长文集候选与片段更长，不能把公开集的低延迟外推到真实 vault。

公开集 7 题排名提升、0 题退步、33 题不变；私有集 11 题提升、11 题退步、18 题不变。这里把未进入前 10 条的排名记为 11，仅用于比较，不能区分候选外与排在第 11–30 名。

## 哪些问题改善、哪些退步

公开集改善的例子（保留固定题目 ID）：

| 类型 | 题目 | BM25 排名 → 重排排名 |
| --- | --- | --- |
| 精确词遇到近似主题 | `queue-1`：为什么要用消息队列 | 2 → 1 |
| 口语描述并发编辑 | `optimistic-lock-2`：两个人同时编辑 数据 怎样避免后保存覆盖前一个 | 6 → 1 |
| 口语描述全表扫描 | `index-2`：数据库 查一条数据却扫了整张表 怎么查 | 8 → 2 |

公开集没有排名退步的题目，不编造退步例子。有 4 题仍不命中，期望文档均未进入 BM25 Top 30 候选；例如同时重试导致服务变慢的问法（`timeouts-2`）、候选缺证据的问法（`rag-2`）、分块过短的问法（`chunk-2`）。更换重排器不能补回候选池外的答案。

私有集只描述问题类型，不公开逐题 ID、原文、路径或标题：

- 改善类型示例：带具体约束的技术配置问法、英文缩写与中文概念对照、口语化的边界或故障因果问题。部分原本靠后的期望文档移到了首位，也有原本前 10 条缺失的期望文档进入结果。
- 退步类型示例：隐喻或故事细节定位、要求多个概念一起对照的长文问题、长期复用与实践结论类问题。有首位答案被挤出前 10 条的情况，私有 Recall@5 从 92.5% 变为 90.0%。
- 已观察到的边界是：BM25 使用全文排序及现有标题 / 路径权重，而重排只看命中片段和标题，不能看到整本长文的上下文。片段不包含真正证据、或相邻资料表述近似时，重排可能偏离人工指定路径。这是机制上的可能原因，不能把所有退步都归因于模型理解能力；本次未对错题重标或调参。

## 模型、下载与加载

使用默认 `BAAI/bge-reranker-base`，没有替换模型：实测 fastembed 0.8.1 的 `TextCrossEncoder.list_supported_models()` 包含它。模型版本 `2cfc18c9415c912f9d8155881c133215df768a70`，MIT 许可；[官方 fastembed 支持列表](https://qdrant.github.io/fastembed/examples/Supported_Models/) 和 [模型仓库](https://huggingface.co/BAAI/bge-reranker-base) 可核查。

- ONNX 文件：1,112,459,588 字节（1.112 GB，约 1.036 GiB）。空缓存下载后的文件总量含分词器和缓存元数据为 1,129,562,295 字节（1.130 GB）。这不是网络流量抓包值，不含传输协议开销。
- 空缓存下载并加载：199.89 秒；构造器计时，不含 Python 导入。首次下载受网络影响很大。
- 已有缓存的公开评测进程初始化：2.16 秒，包含可选模块导入和模型加载；模型在 MCP 进程中复用。空缓存测量记录见 [model-measurement.json](model-measurement.json)。
- 输入只用文档标题（最多 256 字符）和现有命中片段（最多 1000 字符），再交给 fastembed 的分词和截断逻辑；不把全文交给交叉编码器。候选池默认 30，请求 limit 更大时扩大到 limit，最多 100。
- 不引入 PyTorch，不使用向量库，不调用在线推理服务。首次下载需要网络，随后可设 `HF_HUB_OFFLINE=1` 使用现有缓存。真实 MCP stdio 已在离线模式下连续调用两次并核实 `rerank_score`、稳定结果与 `read_range` 定位。

## 复现与验证

从仓库根目录一条命令跑公开基线和重排（首次运行会下载模型）：

```sh
uv run --extra rerank python evals/compare.py
```

输出 `evals/public-bm25.json` 和 `evals/public-rerank.json`。可加 `--output-dir <目录>` 保存新测量；延迟会浮动。已用离线缓存再次运行这条命令，两次准确率和每题排名完全一致。逐步命令与私有参数见 [evals/README.md](README.md)。

私有复现使用同一个 runner，在固定的只读快照上分别运行：

```sh
uv run --extra rerank python evals/run.py --vault <固定快照> --questions <仓库外的问题.jsonl> --mode bm25 --summary-only --output <库外>/bm25.json
uv run --extra rerank python evals/run.py --vault <固定快照> --questions <仓库外的问题.jsonl> --mode rerank --summary-only --output <库外>/rerank.json
```

私有汇总见 [基线](private-bm25-summary.json) 和 [重排](private-rerank-summary.json)。题目 SHA-256 和快照指纹一致；快照测后再次校验哈希，确保没有改变。评测脚本拒绝把输出写进被评测的 vault 或覆盖问题文件。

验证：原有 69 个测试 + 新增 25 个测试，共 94 个，安装 / 不安装可选依赖的环境均通过；`uv build` 成功构建 wheel 与源码包。缺依赖环境的安装后 wheel 也实际搜索并退回 BM25。结构化自检未发现阻塞项；没有另行启动独立 reviewer，PR 留给 Claude 审查，不合并。

缺依赖、加载失败、推理失败、分数数量错误或非有限分数都会记录不含私有文本的警告并回退原 BM25；失败状态保持到进程重启，避免反复下载。没有按评测结果更改题目、答案、语料或 BM25 常量。保留默认关闭，是因为私有场景的提升不足以证明应为所有用户承担该延迟。
